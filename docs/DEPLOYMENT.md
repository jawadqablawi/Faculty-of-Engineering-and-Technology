# نشر ETCS على خادم دائم

هذه التعليمات تجهز خادماً واحداً باستخدام Docker Compose. يلزم خادم Linux مع Docker/Compose، دومين موجه إلى عنوان الخادم، ومزود SMTP. لا تنشئ هذه الملفات استضافة أو دومين، ولا تعني أن الموقع منشور بالفعل.

## 1. تنزيل المشروع وإنشاء الإعدادات

```bash
git clone https://github.com/jawadqablawi/Faculty-of-Engineering-and-Technology.git
cd Faculty-of-Engineering-and-Technology
python3 scripts/prepare_deploy.py --domain YOUR_REAL_DOMAIN
```

استبدل `YOUR_REAL_DOMAIN` باسم نطاقك فقط دون https أو مسار. ينشئ الأمر ملف `.env` بصلاحية 0600، بمفاتيح وكلمات مرور عشوائية، ويرفض استبدال ملف موجود. لا تضعه في GitHub ولا تشارك محتوياته في المحادثات. قاعدة البيانات الأولية لا تحتوي حسابات أو كلمات مرور مشتركة.

عدّل حقول SMTP داخل `.env` بمحرر على الخادم: `ETCS_EMAIL_HOST`, `ETCS_EMAIL_PORT`, `ETCS_EMAIL_USER`, `ETCS_EMAIL_PASSWORD`, `ETCS_FROM_EMAIL`. يجب أن يسمح مزود البريد بالإرسال باسم العنوان المحدد. افحص قواعد الإرسال والاتصال الخاصة بمزودك. يتيح `ETCS_EMAIL_NOTIFICATIONS=1` إرسال التنبيهات الإضافية من طابور قابل لإعادة المحاولة؛ الدعوات واستعادة كلمة المرور تستخدم المزود مباشرة.

## 2. التشغيل

```bash
docker compose up -d --build
```

الخدمات:

- `database`: PostgreSQL 17 على شبكة داخلية، دون نشر منفذ قاعدة البيانات.
- `migrate`: تهيئة الجداول والنوادي وسياسات RLS ومنح حساب الويب المحدود.
- `web`: Gunicorn بعمليتين، دون منفذ مباشر على الإنترنت، وبحساب Linux غير جذري وحساب PostgreSQL لا يتجاوز RLS.
- `reminders`: تذكيرات وطابور بريد كل خمس دقائق، مع إعادة تشغيل تلقائية.
- `gateway`: Caddy لاستقبال 80/443 وإصدار وتجديد شهادة HTTPS للدومين بعد صحة DNS وفتح المنفذين.

الاتصال بـPostgreSQL داخل شبكة الحاويات غير المنشورة يستخدم `sslmode=disable`؛ لخادم قاعدة بيانات خارج هذا الجهاز استخدم TLS الموثق (`verify-full` مع شهادة الجهة المناسبة)، ولا تعرض قاعدة البيانات للعامة. لا تعرض منفذ Gunicorn؛ البوابة تنظف رأس البروتوكول الموثوق.

عند البناء داخل بيئة Codex ذات شهادة الوكيل، ابنِ الصورة أولاً مع حزمة الثقة العامة المدمجة ثم شغّل Compose دون إعادة بناء:

```bash
docker build --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt -t etcs:local .
docker compose up -d --no-build
```

لا تُنسخ شهادة الجلسة إلى الصورة، ولا يُعطل التحقق من TLS. خارج هذه البيئة يكفي البناء العادي.

## 3. إنشاء المنسق ودعوة النوادي

```bash
docker compose run --rm migrate python manage.py bootstrap --email YOUR_REAL_EMAIL
```

يدخل المسؤول كلمة مرور فريدة تفاعلياً دون طباعة قيمتها. يسجل الدخول عبر الدومين، ثم يدعو رئيساً لكل نادٍ من صفحة المستخدمين. الدعوة تتحقق من البريد وتعين كلمة مرور خاصة بالمستخدم؛ تنتهي بعد يومين وتستخدم مرة واحدة. يمكن إلغاء الدعوات المعلقة وتعطيل المستخدمين وتغيير نطاق الصلاحيات من الواجهة. عند انتقال رئاسة النادي، عطّل السابق وادعُ البديل للنادي نفسه؛ السجلات محفوظة.

للنواب: حدد الوحدات **والنوادي** المصرح بها. للمدقق: حدد وحدة التقارير والسجلات المحددة. لا تمنح حساب نائب صلاحية Django superuser أو حساب قاعدة الصيانة.

## 4. التحقق قبل إدخال بيانات حقيقية

```bash
docker compose ps
docker compose exec web python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/healthz/').status)"
docker compose run --rm migrate python manage.py check --deploy
```

افتح الموقع عبر الدومين واختبر دعوة إلى بريد اختبار تملكه واستعادة كلمة المرور. نفذ طلباً بحساب نادٍ وتحقق من متابعته بحساب المنسق. افحص تحميل ملف مسموح ومنع النادي الثاني من تنزيله. تتطلب تحذيرات HSTS الخاصة بجميع النطاقات الفرعية/preload قرار صاحب الدومين؛ لا تفعلها دون ضمان HTTPS لكل النطاقات المتأثرة. لا تعتبر الوصول إلى صفحة الدخول إثباتاً لوصول رسائل SMTP أو صدور شهادة للدومين؛ تحقق من كل منهما بالفعل.

## 5. النسخ الاحتياطي والاستعادة

أوقف الكتابة مؤقتاً لضمان اتساق الملفات مع قاعدة البيانات. لا تحذف المجلدات الدائمة:

```bash
mkdir -m 700 -p .backups
docker compose stop web reminders
docker compose run --rm -v "$PWD/.backups:/backups" migrate python manage.py backup /backups/UNIQUE_BACKUP_NAME
docker compose start web reminders
```

قد تحتاج تهيئة ملكية مجلد النسخ لصاحب UID 10001 على الخادم، دون إعطاء صلاحية قراءة عامة. يشمل النسخ `database.dump` و`private_media/`. احتفظ بـ`.env` بصورة آمنة منفصلة. انقل نسخاً مشفرة إلى مخزن خارج الخادم واختبر الاستعادة دورياً. لا توجد خدمة نسخ خارجي مفعلة تلقائياً.

للاستعادة إلى **قاعدة جديدة فارغة** على بيئة منفصلة، أنشئ حساب الويب المحدود، ثم استخدم `pg_restore --no-owner --no-acl` بحساب الصيانة، وأعد الملفات الخاصة إلى وحدة التخزين بملكية UID 10001، ثم شغّل migrations و`grant_web_role etcs_web`. شغّل التطبيق على النسخة المستعادة وتحقق من عدد السجلات وتنزيل مرفق مصرح. لا تختبر الاستعادة على قاعدة التشغيل. يجب أن يكون إصدار أدوات `pg_dump/pg_restore` متوافقاً؛ صورة المشروع تتضمن عميل PostgreSQL 17.

## 6. التحديث

خذ نسخة احتياطية، ثم:

```bash
git pull --ff-only
docker compose up -d --build
```

تعاد خدمة التهيئة لتطبيق migrations الجديدة ومنح الجداول الجديدة لحساب الويب قبل تشغيله. لا تعِد توليد مفاتيح `.env` أو تبدل كلمات مرور القاعدة دون إجراء تدوير واعٍ على PostgreSQL نفسه. تجنب `docker compose down -v` على بيئة التشغيل؛ يحذف البيانات الدائمة.

## حدود التشغيل الفعلية

الاختبارات المحلية تشمل SQLite وPostgreSQL بحساب محدود وواجهة المتصفح وصورة Docker. إصدار شهادة لدومين عام، توصيل SMTP حقيقي، النسخ الخارجي، واستضافة مدفوعة تتطلب موارد صاحب الموقع ولم تُنفذ باسم المستخدم. مشاركة شريك في نشاط لا تمنحه الوصول لبيانات النادي. موافقات الجهات تسجل بمراجع الأدلة من المستخدم المخول؛ النظام لا يصادق على القرار نيابة عن الجامعة ولا ينتحل توقيعاً رسمياً.
