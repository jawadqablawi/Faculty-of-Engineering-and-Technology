# نشر ETCS على Vercel مع Neon Free

هذا مسار مختلف عن Docker: Vercel يشغّل Django كدالة Python، وNeon يحفظ السجلات **والمرفقات الخاصة** في PostgreSQL. لا تحتاج إضافة Object Storage للبدء. الخطط المجانية لها حصص وقد تتوقف الخدمة عند بلوغها؛ لا تفعل ترقية مدفوعة أو تضف وسيلة دفع إذا كنت تريد المجاني فقط.

## إعداد الواجهة

في استيراد مستودع GitHub إلى Vercel:

- Application Preset: **Django**.
- Root Directory: `./`.
- اختر مشروعاً على **Hobby**، وقاعدة Neon على **Free** في Frankfurt.
- اترك Build Settings الافتراضية؛ `vercel.json` يحدد أمر البناء والمنطقة.

## المتغيرات السرية

أضف القيم التالية إلى **Production فقط** في Environment Variables، دون علامات تنصيص. لا ترسل القيم السرية في المحادثات أو الصور ولا تضعها في GitHub.

| Key | Value |
|---|---|
| `DATABASE_URL` | رابط Neon الكامل المجمّع، الذي يحتوي `-pooler`، مع كلمة مروره الفعلية وإعدادات TLS |
| `ETCS_RLS` | `1` |
| `ETCS_SECRET_KEY` | مفتاح عشوائي خاص لا يقل عن 50 حرفاً |
| `ETCS_OWNER_EMAIL` | البريد الذي ستدخل به كمنسق |
| `ETCS_OWNER_PASSWORD` | كلمة مرور جديدة قوية خاصة بالمنسق |
| `CRON_SECRET` | مفتاح عشوائي آخر لحماية التذكيرات المجدولة |

لتوليد مفتاح محلياً على ويندوز دون إظهاره، افتح PowerShell وشغّل:

```powershell
([guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')) | Set-Clipboard
```

الصق الناتج في قيمة `ETCS_SECRET_KEY`. كرر الأمر لتوليد قيمة **مختلفة** لـ`CRON_SECRET`. احتفظ بالمفاتيح في مدير كلمات مرور. لا تغيّر `ETCS_SECRET_KEY` بعد النشر دون إجراء تدوير واعٍ: يتأثر به تسجيل الدخول وكلمة مرور حساب قاعدة البيانات المحدود المشتقة منه.

لا تضف `ETCS_DEBUG=1` أو `ETCS_DEPLOY_PREPARE` أو رابط localhost إلى إعداد الإنتاج. أسماء النطاقات ومصادر CSRF تؤخذ تلقائياً من روابط مشروع Vercel الموثوقة؛ للدومين المخصص أضف اسمه في `ETCS_ALLOWED_HOSTS` ومصدره https في `ETCS_TRUSTED_ORIGINS`.

## البناء الأول

بعد تحديث GitHub وإكمال المتغيرات اضغط **Deploy**. أمر البناء يقوم بـ:

1. تطبيق migrations وإنشاء خمسة نوادٍ.
2. إنشاء أول منسق من متغيري البريد وكلمة المرور، مع تجزئة آمنة للكلمة وعدم طباعتها. لا يستبدل حساباً موجوداً ولا يعيد تعيين كلمة مروره في البناء التالي.
3. إنشاء حساب SQL محدود لا يملك الجداول ولا BYPASSRLS، ومنحه صلاحيات التشغيل. كلمة مروره مشتقة من مفتاح التطبيق وتظل على الخادم.
4. تجهيز التقويم العام الآمن. يجمع Vercel ملفات Django الثابتة تلقائياً.

رابط Neon الأساسي يستخدم للتهيئة داخل البناء؛ إعداد التطبيق يحوّل اتصالات الطلبات تلقائياً إلى الحساب المحدود. صلاحيات HTTP وRLS لا تعتمد على متغير club_id يرسله المتصفح. يتطلب التحضير أن يسمح رابط مالك مشروع Neon بإنشاء أدوار SQL، كما في المشروع الجديد المعتاد. لا نستخدم حساب Neon الإداري مباشرةً للطلبات. يحتفظ Vercel بمتغيرات البيئة على الخادم؛ حماية حساب Vercel وNeon ضرورية، لأن اختراق خادم موثوق أو متغيراته ليس ضمن حماية RLS ضد أخطاء الاستعلام.

أدوار Neon المنشأة من Console قد ترث صلاحية تجاوز RLS؛ لذلك ينشأ حساب التشغيل بـSQL ولا يرث دور `neon_superuser`. راجع [توثيق Neon للأدوار](https://neon.com/docs/manage/roles).

عندما تصبح الحالة **Ready**، افتح رابط `.vercel.app` وسجّل ببريد المنسق وكلمة مروره التي اخترتها. بعد التأكد من تسجيل الدخول، يمكنك إزالة `ETCS_OWNER_PASSWORD` من المتغيرات وإعادة النشر؛ الحساب محفوظ ولن يعاد إنشاؤه أو تغيير كلمته.

## البيانات والمرفقات وPDF

- لا تستخدم SQLite أو نظام ملفات Vercel لحفظ سجلات أو مرفقات؛ كلاهما غير دائم هناك. يرفض الإعداد التشغيل دون PostgreSQL وRLS.
- المرفقات والشعارات تحفظ في جدول خاص وتُقرأ من مسارات تتحقق من هوية المستخدم وصلاحياته، دون رابط ملفات عام. تشملها النسخة الاحتياطية لقاعدة البيانات.
- الحد في هذا المسار **3 ميغابايت للملف** لمراعاة حجم طلب الدوال. التخزين يشترك مع حصة Neon المجانية، لذلك راقب الاستخدام وتجنب رفع فيديو أو صور ضخمة.
- PDF العربي يستخدم fpdf2 مع تشكيل HarfBuzz وخط مضمن مرخص، فلا يحتاج مكتبات Pango غير المتاحة عادةً في الدوال. يبقى مسار Docker يستخدم WeasyPrint.

## البريد والتذكيرات

تسجيل الدخول وإنشاء حساب المنسق لا يحتاجان مزود إرسال بريد، لكن الدعوات واستعادة كلمة المرور تحتاج إعداد SMTP حقيقي. يمكن ربط حساب Gmail مؤهل باستخدام كلمة مرور تطبيق خاصة بعد تفعيل التحقق بخطوتين؛ **لا تستخدم كلمة مرور حساب Google الأساسية**. ضع بياناته في Vercel فقط: `ETCS_EMAIL_HOST`, `ETCS_EMAIL_PORT`, `ETCS_EMAIL_USER`, `ETCS_EMAIL_PASSWORD`, `ETCS_FROM_EMAIL`. لا تعتبر الإرسال متصلاً قبل اختبار رسالة إلى بريد تملكه.

الجدولة المضمنة في `vercel.json` مرة يومياً الساعة 06:00 UTC، وفق المسار المناسب لخطة Hobby. تحديثات الطلبات تنشئ إشعارات داخلية فوراً؛ التذكيرات المجدولة في هذا المسار يومية، وليست كل خمس دقائق مثل خادم Docker. مسار cron يرفض الطلبات دون Authorization صالح مطابق لـ`CRON_SECRET`. يمكن تفعيل بريد الإشعارات الاختياري بـ`ETCS_EMAIL_NOTIFICATIONS=1` بعد نجاح SMTP؛ يعالج cron طابوره.

## التحقق والحدود

اختُبر المسار محلياً بوضع `VERCEL=1` وقاعدة PostgreSQL ودور مالك غير superuser وحساب تشغيل محدود، مع الملفات الدائمة وعزل النوادي وPDF العربي ودورة الموافقات والتقويم وcron. أداة الاختبار `scripts/vercel_smoke.py` تنشئ قاعدة مؤقتة على `ETCS_TEST_DATABASE_URL` وتحذفها. اختبارات محلية لا تعني أن حساب Neon الحقيقي أو بناء Vercel الفعلي قد نجح؛ تحقق من Build Logs وتسجيل الدخول والرفع بعد النشر.

تحظر أداة التحضير كتابة قاعدة الإنتاج من Preview افتراضياً. لا تنسخ بيانات Production إلى Preview؛ استخدم قاعدة اختبار منفصلة وأذن لها صراحةً إذا أردت ذلك. لا تُحذف البيانات أو يعاد تعيين الحسابات عند Redeploy.
