# ETCS — نظام تنسيق كلية الهندسة والتكنولوجيا

نظام إداري عربي باتجاه RTL لجامعة فلسطين التقنية – خضوري، مبني على Django 5.2 LTS وقاعدة بيانات فعلية. يدير خمسة نوادٍ أولية مع إمكانية إضافة نوادٍ وتعطيلها.

## رابط على Vercel

للنشر على Vercel مع Neon Free اتبع [التعليمات المخصصة هنا](docs/VERCEL.md). هذا المسار يحفظ الملفات في PostgreSQL ويستخدم PDF مناسباً للدوال، ولا يحتاج Docker على جهازك.

## ما يتضمنه

- تسجيل دخول فردي، دعوات تتحقق من البريد، استعادة كلمة المرور، تعطيل فوري للحسابات، صلاحيات للنائب والمراجع والمدقق، وحدود لمحاولات الدخول مشتركة بين عمليات الخادم.
- أربع خطوات للفعاليات الوجاهية، مسودات وحفظ تلقائي قابل لإعادة المحاولة، أيام إضافية، احتياجات وميزانية دقيقة، برنامج ومتحدثون وشراكات ومرفقات خاصة بإصدارات وبصمات ملفات.
- نموذج مستقل للورش الإلكترونية، جلسات مخزنة في جداول، وخطة إعلان ونشر بمواعيد ومسؤولين وحالات وأدلة نشر.
- مراجعة وتعديلات ورفض بأسباب، موافقة أولية، رفع للمجلس، موافقات المجلس والجامعة وجهات إضافية إلزامية لا يمكن تجاوزها، وسجل نسخ وتعليقات وأدلة قرارات.
- كتب رسمية بنسخ محفوظة وأرقام داخلية مستقلة عن الرقم الرسمي، وتواريخ إرسال ورد ومتابعة وتصدير PDF عربي.
- تقويم شهر/أسبوع/يوم، أنشطة وجلسات وأيام إضافية واجتماعات ومواعيد نشر، وتحذير تعارض المكان، وتصدير ICS بالتوقيت الصحيح. لا يكشف التقويم تفاصيل نادي آخر الخاصة ولا يحجز القاعات تلقائياً.
- ملفات نوادٍ وشعارات وخطط شهرية، اجتماعات وقرارات، مهام مسندة، شؤون طلبة بملفات خاصة وتكليف ومتابعة وإزالة بيانات بعد فترة الاحتفاظ.
- تقارير أسبوعية وشهرية وسنوية وبحسب النادي، الحضور الفعلي، الطلبات المعلقة والمكتملة والورش، تقارير خاصة بالقضايا والكتب والمهام، Excel/PDF، وأرشيف حسب العام والفصل.
- تقارير ختامية وتصحيحات وقبول وإغلاق، إشعارات وتذكيرات متكررة دون تكرار في اليوم نفسه، بريد اختياري بطابور إعادة محاولة، وسجل تدقيق لا يملك حساب الويب تعديلَه أو حذفَه في PostgreSQL.

## فتح الموقع على ويندوز

1. ثبّت [Docker Desktop](https://www.docker.com/products/docker-desktop/) وشغّله. إذا طلب تفعيل WSL 2 أو إعادة تشغيل ويندوز، أكمل تعليمات المثبت.
2. نزّل المشروع من GitHub بصيغة ZIP وفك ضغطه إلى مجلد عادي.
3. افتح `START-WINDOWS.bat` بالنقر المزدوج. أول تشغيل يحتاج إنترنت ووقتاً لتنزيل الحزم.
4. أدخل بريدك وكلمة مرور جديدة لحساب المنسق. الأحرف لا تظهر أثناء كتابة كلمة المرور. يفتح المتصفح تلقائياً على `http://localhost:8000`.

في التشغيلات اللاحقة استخدم الملف نفسه ثم ادخل بحسابك الموجود. `STOP-WINDOWS.bat` يوقف الموقع دون حذف البيانات. البيانات محفوظة في وحدة Docker باسم المشروع `etcs-windows`؛ لا تحذفها من Docker Desktop إذا أردت الاحتفاظ بحساباتك وملفاتك. هذا عرض محلي على جهازك فقط؛ البريد فيه وضع تطوير ولا يرسل رسائل فعلية. للاستضافة العامة استخدم تعليمات النشر أدناه.

## تشغيل محلي

```bash
python3 -m venv /workspace/etcs-venv
/workspace/etcs-venv/bin/pip install -r requirements.lock.txt
export ETCS_DEBUG=1
/workspace/etcs-venv/bin/python manage.py migrate
/workspace/etcs-venv/bin/python manage.py bootstrap
/workspace/etcs-venv/bin/python manage.py bootstrap --email YOUR_EMAIL
/workspace/etcs-venv/bin/python manage.py collectstatic --noinput
/workspace/etcs-venv/bin/python manage.py runserver 127.0.0.1:8000 --noreload
```

أدخل بريدك الحقيقي بدلاً من `YOUR_EMAIL`، ثم كلمة مرور خاصة تفاعلياً. لا توجد كلمات مرور افتراضية أو حسابات نوادٍ مشتركة. البريد المحلي الافتراضي يطبع روابط التطوير في مخرجات الخادم؛ لا يرسل رسائل فعلية. لا تشارك هذه الروابط لأنها رموز تفعيل/استعادة. شغّل `python manage.py runreminders` بعملية مستقلة للتذكيرات وطابور البريد.

SQLite مناسبة للتطوير. يتم اختيار PostgreSQL عبر `DATABASE_URL`. نشر Compose يشغل PostgreSQL مع RLS وحساب ويب محدود وGunicorn وملفات خاصة دائمة وCaddy لـHTTPS وعامل تذكيرات. **الأكواد وملفات النشر لا تنشئ استضافة أو رابطاً عاماً تلقائياً.**

## الاختبارات

```bash
ETCS_DEBUG=1 /workspace/etcs-venv/bin/python manage.py test
ETCS_DEBUG=1 /workspace/etcs-venv/bin/python scripts/browser_smoke.py
```

اختبار المتصفح يحتاج Node.js وPlaywright وChromium، ويستخدم قاعدة مؤقتة ببيانات اصطناعية. ينتج لقطات في `/tmp/etcs-browser-artifacts` دون تغيير قاعدة التطوير.

لاختبار PostgreSQL/RLS على خادم اختبار منفصل:

```bash
ETCS_TEST_DATABASE_URL='YOUR_DEDICATED_TEST_ADMIN_CONNECTION' /workspace/etcs-venv/bin/python scripts/postgres_smoke.py
```

ينشئ الاختبار قاعدة وحساباً مؤقتين ويحذفهما، ويتحقق من العزل دون مرشح ORM، ومنع الوصول للملفات، والدعوات والموافقات والتقويم بحساب ويب محدود. يحتاج صلاحية إنشاء قواعد وأدوار على خادم الاختبار. لا تشغله على بيانات الإنتاج.

## النشر والوثائق

- [تعليمات النشر والنسخ والاستعادة](docs/DEPLOYMENT.md)
- [البنية والصلاحيات](docs/ARCHITECTURE.md)
- `compose.yaml` و`Dockerfile` لتشغيل خادم واحد مع PostgreSQL وHTTPS.
- `.env.example` أسماء الإعدادات فقط؛ `scripts/prepare_deploy.py` يولد ملفاً خاصاً دون طباعة الأسرار أو استبدال ملفات موجودة.
- GitHub Actions يشغل الاختبارات وmigrations وفحص PostgreSQL/RLS.

SMTP الحقيقي وشهادة الدومين والاستضافة والنسخ الخارجي تحتاج إعداد صاحب الموقع. لا ينشر النظام إلى شبكات التواصل تلقائياً؛ يسجل خطط النشر وإثباتات تنفيذها. لا تُولد توقيعات رسمية ولا تُنسب موافقة لجهة دون إجراء مسجل. الملفات تُفحص من حيث الحجم والنوع وتوقيع المحتوى وبنية Office؛ لا تتضمن النسخة خدمة مضاد فيروسات خارجية. لا توجد بيانات طلبة حقيقية في سجلات الاختبار.
